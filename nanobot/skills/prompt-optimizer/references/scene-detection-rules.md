# 场景识别规则

本文档提供完整的场景识别决策树和规则,用于快速判断用户需求属于哪种场景类型。

## 快速决策树

```
用户输入
   ↓
[步骤1] 单一任务 vs 多步骤?
   ↓
   ├─ 多个步骤 → 场景4:多步骤任务
   │
   └─ 单一任务 →[步骤2] 需要推理 vs 直接处理?
       ↓
       ├─ 需要推理分析 → 场景3:复杂推理
       │
       └─ 直接处理 →[步骤3] 有特定需求?
           ↓
           ├─ 需要风格/创意 → 场景2:创意生成
           ├─ 需要查找信息 → 场景5:研究任务
           ├─ 需要操作工具 → 场景6:工具使用
           ├─ 强调格式要求 → 场景7:格式控制
           └─ 直接文本处理 → 场景1:简单文本处理
```

## 7 大场景详细识别规则

### 场景1:简单文本处理

**关键识别信号**:
- 动词: "总结"、"提取"、"分类"、"改写"、"翻译"
- 特征: 输入输出清晰,无需多步推理
- 复杂度: 简单,单次处理即可完成

**典型表达**:
- "帮我总结这篇文章"
- "从文本中提取所有日期"
- "把这段话改写得更正式"
- "分类这些评论的情感"

**排除条件**:
- 如果需要"先分析再总结" → 场景3或4
- 如果需要特定写作风格 → 场景2
- 如果需要多源查找 → 场景5

---

### 场景2:创意/风格化内容生成

**关键识别信号**:
- 动词: "写"、"创建"、"设计"、"生成"
- 特征: 需要特定语气/风格/视角,面向特定受众
- 关键词: "风格"、"语气"、"受众"、"创意"、"专业"

**典型表达**:
- "写一篇轻松幽默的博客文章"
- "为我们的产品创建营销文案,面向年轻人"
- "生成一份正式的商业报告"
- "用专家的口吻解释这个概念"

**排除条件**:
- 如果只是简单总结 → 场景1
- 如果需要复杂分析 → 场景3

---

### 场景3:复杂分析/推理任务

**关键识别信号**:
- 动词: "分析"、"解决"、"推理"、"计算"、"评估"、"决策"
- 特征: 需要多步骤思考,涉及逻辑推理或权衡
- 关键词: "为什么"、"如何"、"最佳"、"比较"、"评估"

**典型表达**:
- "分析这个商业策略的优缺点"
- "解决这个数学问题"
- "评估这两个方案哪个更好"
- "推理出最可能的原因"

**确认问题**:
- "这个任务需要推理和思考吗?"
- "是否需要权衡多个因素?"
- "用户需要看到推理过程吗?"

---

### 场景4:多步骤/链式任务

**关键识别信号**:
- 时间词: "先"、"再"、"然后"、"接下来"、"最后"
- 特征: 明确的多个步骤,前一步输出是下一步输入
- 关键词: "流程"、"步骤"、"分阶段"

**典型表达**:
- "先总结文档,再提取关键问题,最后生成行动计划"
- "第一步分析数据,第二步生成报告,第三步提出建议"
- "帮我完成这个多步骤的研究任务"

**确认问题**:
- "这个任务有几个主要步骤?"
- "每个步骤的输出是什么?"
- "步骤之间有依赖关系吗?"

---

### 场景5:研究和信息收集

**关键识别信号**:
- 动词: "调查"、"研究"、"查找"、"搜集"、"验证"
- 特征: 需要查找信息,可能需要多源验证
- 关键词: "最新"、"准确"、"来源"、"证据"

**典型表达**:
- "调查一下最新的市场趋势"
- "研究这个技术的发展历史"
- "查找关于X的可靠信息"
- "验证这个说法是否准确"

**确认问题**:
- "需要查找外部信息吗?"
- "需要多源验证吗?"
- "对信息的可靠性有什么要求?"

---

### 场景6:工具使用/代理任务

**关键识别信号**:
- 动词: "帮我"、"修改"、"处理"、"操作"、"执行"
- 特征: 需要使用工具(文件操作、API调用等)
- 关键词: "文件"、"自动"、"批量"

**典型表达**:
- "帮我修改这个文件"
- "批量处理这些图片"
- "自动整理这些数据"
- "执行这个操作"

**确认问题**:
- "希望AI主动操作还是先询问?"
- "需要并行处理吗?"
- "对操作安全性有什么要求?"

---

### 场景7:输出格式控制

**关键识别信号**:
- 明确提到格式要求
- 使用负面表达("不要"、"避免")
- 关键词: "格式"、"结构"、"样式"、"markdown"、"JSON"

**典型表达**:
- "用JSON格式输出"
- "不要使用项目符号"
- "用流畅的段落而不是列表"
- "按照这个格式输出"

**注意**:
- 这通常是**附加**到其他场景的要求
- 可以与其他场景组合使用

---

## 识别流程

### 第一步:快速分类问题

向用户询问这3个关键问题(不一定全部问,根据情况判断):

1. **"这是单一任务还是需要多个步骤?"**
   - 单一 → 继续
   - 多个 → 场景4

2. **"需要推理分析吗,还是直接处理?"**
   - 推理 → 场景3
   - 直接 → 继续

3. **"有输入数据吗?什么格式?"**
   - 帮助判断是场景1、2、5、6还是7

### 第二步:确认场景

基于用户回答和初步判断,明确告知用户识别的场景:

```
"根据您的需求,这属于[场景X:XXX]。我会根据这个场景的最佳实践来优化您的prompt。"
```

### 第三步:针对性提问

根据场景类型,提问3-5个关键问题补充信息。

## 边界情况处理

### 情况1:同时符合多个场景

**处理方式**:
1. 识别主要场景(占比最大的部分)
2. 告知用户:"这个任务主要是[场景X],同时涉及[场景Y]"
3. 按主场景生成prompt,融入次要场景的技术

**示例**:
- "写一篇分析报告" → 主场景2(创意生成) + 次场景3(复杂推理)
- "查找并总结信息" → 主场景5(研究) + 次场景1(简单文本)

### 情况2:用户需求过于模糊

**处理方式**:
1. 不要急于判断场景
2. 先问通用问题澄清需求:
   - "能详细说说您具体想完成什么吗?"
   - "这个任务的最终目标是什么?"
   - "有什么具体的期望或约束吗?"
3. 根据回答再进行场景识别

### 情况3:用户需求超出7大场景

**处理方式**:
1. 告知用户:"这是一个比较特殊的需求"
2. 尝试拆解为已知场景的组合
3. 如实在无法归类,按照通用最佳实践处理:
   - 明确具体的指令
   - 清晰的输出格式
   - 适当的上下文
   - 示例(如适用)

## 提问技巧

### 开放式 vs 封闭式

**开放式**(用于需求澄清):
- "您具体想完成什么?"
- "期望达到什么效果?"

**封闭式**(用于快速确认):
- "这是单一任务还是多步骤?" (二选一)
- "需要150字还是300字?" (具体选项)

### 提问顺序

1. 先问**分类问题**(判断场景)
2. 再问**细节问题**(补充信息)
3. 最后问**边界问题**(特殊情况)

### 避免过度提问

- 单次最多3-5个问题
- 如果用户已经提供了某些信息,不要重复问
- 优先问最关键的信息

## 实战案例

### 案例1:模糊需求

**用户**: "帮我处理一下这个文档"

**识别过程**:
1. 需求过于模糊,无法直接判断场景
2. 提问澄清:
   - "您想对文档做什么处理呢?"
   - 用户: "总结主要内容"
3. 识别: 场景1(简单文本处理)

### 案例2:复合需求

**用户**: "先分析这个市场数据,再写一份报告,语气要专业"

**识别过程**:
1. 明显多步骤 → 首先是场景4
2. 第一步"分析" → 场景3
3. 第二步"写报告+专业语气" → 场景2
4. **最终判断**: 场景4(多步骤),融合场景3和场景2的技术

### 案例3:格式重点

**用户**: "总结这篇文章,但不要用项目符号"

**识别过程**:
1. 核心任务"总结" → 场景1
2. 附加要求"不要项目符号" → 场景7(格式控制)
3. **最终判断**: 场景1(主) + 场景7(辅)
