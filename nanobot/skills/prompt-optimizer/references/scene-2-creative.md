# 场景2: 创意/风格化内容生成

本场景适用于需要面向特定受众与风格的原创内容创作任务,包括故事写作、营销文案、专业文档、以及语气切换等。目标是在遵循官方最佳实践的前提下,以清晰的结构与示例高效引导 Claude 生成一致、可用的创意输出。

## 核心技术

### 1. Role Prompting (角色设定)

**原则**: 使用系统或指令中的角色设定,让 Claude 采用特定身份的语气与决策偏好。

**反模式** ❌:
```
“写一篇文案,尽量专业”
→ 没有角色、语气参考,导致输出风格漂移
```

**最佳实践** ✅:
```
在系统或模板中明确设定角色与职责,例如:
<role>
你是一位资深B2B内容营销专家,擅长以简洁专业的语气向技术决策者传达价值。
</role>
```

### 2. Style Examples (风格示例)

**原则**: 用2-3个简短且格式一致的示例明确风格与语气,示例必须100%一致,避免混杂细节。

**反模式** ❌:
```
<examples>
示例1: 使用幽默语气
示例2: 使用学术语气
</examples>
→ 示例之间风格不一致,容易让 Claude 产生混乱
```

**最佳实践** ✅:
```
<style_examples>
示例1: 语气:正式,句式:简洁,措辞:专业术语
示例2: 语气:正式,句式:简洁,措辞:专业术语
</style_examples>
```

### 3. Audience Definition (受众定义)

**原则**: 明确目标读者的背景、知识水平、动机与痛点,以便选取恰当的解释深度与措辞。

**反模式** ❌:
```
“面向大众”
→ 范围过宽,无法优化语气与内容密度
```

**最佳实践** ✅:
```
<audience>
角色: 技术总监/架构师
知识水平: 熟悉云原生与DevOps
动机: 降低运维成本,提升交付速度
痛点: 工具链复杂,可观测性不足
</audience>
```

### 4. Context & Motivation (上下文与动机)

**原则**: 为创作提供必要背景信息和创作动机,让 Claude 在合适边界内发挥创造力。

**反模式** ❌:
```
“写个故事,要精彩”
→ 缺少题材限制、主题动机与长度范围
```

**最佳实践** ✅:
```
<context>
题材: 科幻,主题: 人机协作与伦理,设定: 近未来城市
动机: 探索AI辅助决策的边界与风险
</context>
```

### 5. Match Prompt Style (匹配Prompt风格)

**原则**: Prompt 的风格会影响输出风格;想要正式输出就用正式语气写 Prompt,避免用与目标相悖的格式与语态。

**反模式** ❌:
```
Prompt 本身充满口语与随意感,但要求输出“学术化、正式”
```

**最佳实践** ✅:
```
以正式语气编写指令、示例与约束,保持整体风格一致
```

### 6. Be Explicit with Instructions (明确具体指令)

**原则**: 明确字数、结构、重点与禁忌,减少生成的歧义与偏差。

**反模式** ❌:
```
“写一篇介绍我们的产品的文章,不要太长”
→ 长度不明确,结构不清晰
```

**最佳实践** ✅:
```
<output_format>
长度: 300-350字
结构: 引言(1段)→要点(2段)→行动建议(1段)
重点: 面向技术决策者,突出可量化收益
禁忌: 不使用夸张形容词,避免空泛口号
</output_format>
```

## Prompt 模板结构

### 基础模板

```xml
<role>
你是一位[角色],面向[受众],以[语气]进行创作。
</role>

<task>
[创意写作/文案/专业文档的具体任务描述]
</task>

<context>
[必要背景信息与创作动机]
</context>

<style_examples>
示例1: [风格示例段落]
示例2: [风格示例段落]
</style_examples>

<output_format>
长度: [具体数字]
结构: [段落/要点/章节]
重点: [聚焦内容]
禁忌: [避免事项]
</output_format>

<input>
[输入材料]
</input>
```

### 增强模板(受众+风格一致性+约束)

```xml
<role>
你是一位[领域]的[资深角色],写作面向[受众-职能/资历],保持[语气与节奏]。
</role>

<task>
生成[类型: 故事/博客/邮件/报告/广告文案]内容。
</task>

<audience>
角色: [如: 技术总监]
知识水平: [如: 熟悉云原生]
动机: [如: 提效降本]
痛点: [如: 工具链复杂]
</audience>

<context>
[题材、主题、场景设定]
</context>

<style_examples>
示例1: [完整段落]
示例2: [完整段落]
</style_examples>

<constraints>
- 语言: [正式/轻松/专业/友好]
- 禁止: [夸张形容词/过度营销话术]
- 术语: [必须/可选]
- 引用: [如需数据,用来源说明]
</constraints>

<output_format>
长度: [字数范围]
结构: [章节/要点/CTA]
风格: [语气与句式]
可读性: [短句/主动语态/信息密度]
</output_format>

<input>
[素材或提纲]
</input>
```

## 常见子任务及最佳实践

### 子任务1: 创意写作(故事/文章)

**关键要素**:
- 题材、主题、世界观设定
- 叙事视角(第一人称/第三人称)
- 风格示例一致性
- 节奏与段落长度

**示例 Prompt**:
```xml
<role>
你是一位科幻短篇作者,语气克制、冷静、具思想性。
</role>

<task>
写一篇800-900字的科幻短篇,探索人机协作的伦理边界。
</task>

<context>
设定: 近未来城市,AI介入公共决策;主题: 人与AI之间的信任与控制。
</context>

<style_examples>
示例1: 语气克制,细节具象,隐喻简练。
示例2: 句式短促,避免夸张辞藻,强调冷静观察。
</style_examples>

<output_format>
结构: 开端(1段)→冲突(2段)→转折(1段)→结尾(1段)
语气: 克制、冷静、具思想性
叙事: 第三人称
</output_format>
```

### 子任务2: 营销文案

**关键要素**:
- 明确受众画像与痛点
- 可量化价值与证据
- 清晰CTA(行动号召)
- 避免夸张或空泛描述

**示例 Prompt**:
```xml
<role>
你是一位B2B营销文案专家,面向技术决策者写作。
</role>

<task>
为“云原生可观测性平台”撰写着陆页主视觉段落(120-150字)。
</task>

<audience>
角色: 技术总监/架构师
动机: 降本增效,减少MTTR
痛点: 工具链分散,告警噪声大
</audience>

<style_examples>
示例1: 语气正式,句式简洁,避免夸张形容。
示例2: 强调可量化收益与具体场景,无营销术语堆砌。
</style_examples>

<output_format>
长度: 120-150字
结构: 价值主张→核心收益→CTA
证据: 至少一个可量化指标(如MTTR减少30%)
禁忌: 不使用“颠覆/革命性”等夸张词
</output_format>
```

### 子任务3: 专业文档(报告/邮件)

**关键要素**:
- 正式语气与结构化表达
- 明确读者与目的
- 专业术语与引用规范
- 行动建议与后续步骤

**示例 Prompt**:
```xml
<role>
你是一位企业架构顾问,撰写正式的技术评估摘要邮件。
</role>

<task>
生成一封250-300字的评估摘要邮件,面向CTO与架构团队。
</task>

<context>
主题: 评估微服务拆分方案的风险与收益;背景: 现有单体系统具性能瓶颈。
</context>

<output_format>
结构: 背景(1段)→评估结论(1段)→建议(1段)
语气: 正式、简洁、具体
术语: 保留必要术语并提供简短解释
</output_format>
```

### 子任务4: 不同语气切换(正式/轻松/专业/友好)

**关键要素**:
- 定义语气特征(句式、用词、情感强度)
- 提供风格示例保持一致性
- 指定长度与结构不变,仅语气替换

**示例 Prompt**:
```xml
<role>
你是一位跨风格写作助手,负责在相同结构中切换语气。
</role>

<task>
将以下同一段内容分别用“正式”“轻松”“友好”三种语气改写。
</task>

<style_examples>
正式: 用词准确、句式较长、语气克制。
轻松: 句式短、用词口语化、轻微幽默。
友好: 温暖、鼓励、主动式表达。
</style_examples>

<input>
[原始段落]
</input>

<output_format>
保持字数±10%不变,结构与信息点一致,仅语气切换。
</output_format>
```

## Claude 4.5 特别注意事项

### 1. 风格匹配与示例一致性

**说明**: Claude 4.5会严格模仿示例中的风格与细节。示例格式必须100%一致,避免混用不同语气与结构。

**对比**:
```
❌ 示例1口语化,示例2学术化 → 输出风格不稳定
✅ 所有示例采用统一语气、句式与措辞 → 输出一致
```

### 2. 简洁沟通与非冗余前言

**说明**: 模型默认倾向简洁直接的沟通风格。若需要更多过渡或修饰,需明确要求;否则将聚焦核心信息。

**实践**:
```
在<output_format>中声明是否允许前言或修辞性开场
```

### 3. 指令明确性优先

**说明**: 字数、结构与禁忌的明确规定能显著提升目标风格的稳定性。

**实践**:
```
提供长度范围、结构层级、重点与禁忌项,并在示例中保持一致
```

### 4. “think”敏感(扩展思考关闭时)

**说明**: 在非扩展思考模式下避免使用“think”,使用“consider/evaluate/analyze”等替代语。

## 常见陷阱

### 陷阱1: 示例风格不一致

❌ 示例混用不同语气或结构 → Claude 复制混杂细节

✅ 示例统一语气、句式、结构 → 输出稳定一致

### 陷阱2: 受众不明确

❌ “面向大众” → 难以控制写作深度与术语

✅ 明确职能/资历/知识水平 → 精准匹配内容密度

### 陷阱3: 目标与动机缺失

❌ “写个故事/文案,要精彩” → 无边界

✅ 题材/主题/场景/动机/长度/结构 → 可控性强

### 陷阱4: 指令仅用负面限制

❌ “不要口语化,不要夸张”

✅ “采用正式语气,短句,避免夸张形容词,突出可量化收益”

### 陷阱5: Prompt风格与目标输出不匹配

❌ Prompt 用口语+列表,要求学术化散文

✅ Prompt 与目标输出风格保持一致(正式散文)

## 质量检查清单

生成前确认:
- [ ] 是否明确角色设定与职责?
- [ ] 是否提供2-3个风格一致的示例?
- [ ] 是否清晰定义受众画像与动机?
- [ ] 输出格式是否包含长度/结构/重点/禁忌?
- [ ] Prompt 风格是否与期望输出风格一致?
- [ ] 是否采用正面描述而非仅负面限制?
- [ ] 示例是否100%一致且无混杂细节?
- [ ] 是否避免空泛营销用语并加入具体证据?
- [ ] 是否提供至少2-3个完整可用示例?
- [ ] 是否遵循XML代码块格式与可解析结构?

## 参考与官方要点摘录

- 匹配 Prompt 风格以影响输出风格;若出现风格可控性问题,尽量使 Prompt 的风格与期望输出一致。[Claude Docs: Prompting best practices]
- 明确指令与结构、长度、禁忌;避免仅使用负面限制。[Claude Docs: Be explicit with your instructions]
- 通过系统提示设定角色,调整沟通风格与语气;适用于需要身份与角色的创作任务。[Claude Docs: System prompts / Role prompting]

---

## 开发者提示

- 若需要严格的格式一致性(如JSON模式),优先考虑结构化输出机制;创意场景通常在风格一致性与受众匹配上更关键。
- 创建风格示例时,保持句式、措辞、语气完全一致,避免引入无关细节(如表情符号或特殊格式)造成偏差。
- 为营销与专业文档加入可量化证据,避免空泛口号,提高可信度。

---

## 结语

创意/风格化内容生成的关键是:明确的角色设定、风格示例的一致性、清晰的受众定义与上下文动机,以及与目标输出匹配的 Prompt 风格。通过正面、具体的指令与结构化的模板,可显著提升 Claude 的创作稳定性与实用性。
